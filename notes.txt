In scope:

Titles — a single "title" entry: name, type (manga/manhwa/manhua/novel/anime), and maybe a link if it's official/legal to read/watch.
Per-user status — each of you can mark a title as want-to-read / in-progress / completed, independently. This is the join table I mentioned — status belongs to the person, not the title.
Per-user rating + note — a simple score (stars or 1–10) and a short remark, once completed. This is the "exchange remarks" behavior you already do, just persisted instead of lost in chat.
Adding a title — either of you can add one, optionally tagging it as "recommended for [the other person]."
A basic list view — see all titles, filter by status, see both of your ratings side by side.

feat: — a new feature (e.g. feat: add character detail page)
fix: — a bug fix (e.g. fix: correct email key in signInWithPassword)
chore: — maintenance stuff that isn't a feature or fix — dependency bumps, config tweaks, renaming files, build script changes (e.g. chore: update supabase-js to v2.45)
docs: — documentation only changes
style: — formatting/whitespace, no logic change (not CSS styling — confusingly named, it means code style)
refactor: — restructuring code without changing behavior
test: — adding or fixing tests
perf: — performance improvements
